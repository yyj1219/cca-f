SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: Your team enabled Anthropic's managed Claude Code Review on GitHub pull requests. To tune it, you wrote detailed criteria into the project's CLAUDE.md: report logic bugs and security vulnerabilities, skip findings in generated protobuf files, and skip subjective naming suggestions. Review comments on subsequent pull requests still flag generated files and naming. What is the most reliable way to make these report and skip criteria take effect?

**선택지**:
1. Create a REVIEW.md that uses @ import syntax to pull the criteria in from CLAUDE.md so both configuration surfaces stay synchronized
2. Add a pipeline step that filters posted review comments by keyword, dropping any finding that mentions generated files or naming choices
3. Write the report and skip criteria directly into a root-level REVIEW.md file so the review agents apply them when flagging and ranking findings => 정답
4. Move the criteria to the top of CLAUDE.md and mark them IMPORTANT so the review agents weight them more heavily than surrounding project rules

**설명**:
- Claude Code Review 기능은 프로젝트 루트 디렉터리에 위치한 REVIEW.md 파일을 코드 검토 전용 프롬프트 및 가이드라인 파일로 우선 참조합니다.
- CLAUDE.md는 주로 CLI 기반의 대화형 Claude Code agent가 프로젝트 개발, 빌드, 테스트 가이드 등을 참조하는 용도인 반면, GitHub PR 자동 검토를 수행하는 Review Agent는 REVIEW.md에 정의된 검토 규칙(Review criteria)을 핵심 지침으로 수용합니다.

**문제 구분 포인트, 어려운 표현**:
- detailed criteria: 세부 기준
- security vulnerabilities: 보안 취약점
- subjective naming suggestions: 주관적인 명명 제안
- subsequent: 이 후의, 뒤이어 일어나는
- reliable: 신뢰할 수 있는
