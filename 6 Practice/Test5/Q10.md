SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: Your pipeline invokes Claude Code with the -p flag to review pull requests. The team keeps its review criteria in docs/review-criteria.md, and the root CLAUDE.md references the file with the line: See `@docs/review-criteria.md` for the standards to apply. The file exists at that path, yet CI review runs consistently ignore the documented criteria. What should you change so the criteria are loaded?

**선택지**:
1. Rewrite the reference as an absolute path to the criteria file, in case the relative path resolves incorrectly in the CI environment
2. Remove the backticks around the file path, since import parsing skips paths inside code spans and treats them as literal text => 정답
3. Move the criteria into a CLAUDE.local.md file at the project root so they load automatically alongside the project memory
4. Move the criteria into a path-scoped rule file under .claude/rules/ with a glob pattern matching the repository's source files => 백틱 파싱 오류를 수정하는 것보다 불필요하게 구조를 변경하는 방법이라서 오답

**설명**:
- Claude Code 환경의 CLAUDE.md 파일에서는 @ 기호를 사용하여 외부 파일의 내용을 동적으로 가리키거나 로드(Import)할 수 있습니다.
- 하지만 Markdown 파서가 CLAUDE.md 내의 파일 참조를 수집하고 가져올 때, 백틱(`)으로 둘러싸인 코드 스팬(Inline Code Span) 내부의 문자는 실행 가능한 가져오기 구문이 아니라 단순한 '리터럴 텍스트(Literal text)'로 취급됩니다.
