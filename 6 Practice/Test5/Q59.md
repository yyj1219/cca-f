SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: The nightly test-generation batch of 5,000 requests ends with request_counts showing 4,850 succeeded and 150 errored. Streaming the results file, you see that most errored entries contain an invalid_request_error stating the prompt is too long (several requests included very large generated files whole), while a smaller number show server errors. What is the correct way to recover the 150 failed analyses?

**선택지**:
1. Retry all 150 failed requests unchanged in a new batch, relying on transient error resolution to clear both error types on the second attempt
2. Resubmit the full 5,000-request batch unchanged to simplify bookkeeping, since errored requests are not billed and only the failures will incur new charges
3. Isolate the failed requests **by custom_id**, **chunk the inputs** behind the context-window errors, and resubmit only those requests in a new batch => 정답
4. Route the 150 failed requests through the synchronous Messages API unchanged, since the context-window errors only apply to batched requests

**설명**:
- Anthropic / OpenAI 등의 Batch API를 활용할 때 발생하는 오류는 크게 두 가지 유형으로 나뉩니다:
  - 클라이언트 측 오류 (invalid_request_error): 입력 토큰이 모델의 컨텍스트 창(Context Window)을 초과한 경우로, 동일한 입력으로 재시도하면 100% 확률로 다시 실패
  - 서버 측 오류 (server_error / 5xx 등): 일시적인 서버 과부하 등으로 발생한 오류로, 재시도 시 성공할 수 있음
- (프롬프트 초과) 건에 대해 대용량 파일 입력 데이터를 적절히 분할(Chunking)하여 컨텍스트 창 제한 내로 맞추고, 새로운 배치로 재전송하는 것이 자원을 절약하고 확실하게 복구하는 올바른 방법임.
