SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow with custom slash commands, CLAUDE.md configurations, and understand when to use plan mode vs direct execution.

QUESTION: The team's code-reviewer subagent is restricted to Read, Grep, and Glob and reviews dozens of diffs every day. A few times per week, a review uncovers a defect whose fix spans several modules and requires updating related tests, work that also depends on edits other subagents made earlier in the same session. A teammate proposes expanding the reviewer's toolset so it can apply these fixes itself. How should this occasional need for code changes be handled?

**선택지**:
1. Give the reviewer the same full tool access as the main agent so a missing capability can never block a review
2. Grant the reviewer Edit and Write access, **with prompt instructions** to modify code only after a finding has been confirmed
3. Add a scoped apply_fix tool to the reviewer that executes the multi-file changes it specifies in a single tool call
4. Keep the reviewer analysis-only and have it return structured fix **recommendations for the main agent** to apply or delegate => 정답

**설명**:
검토자가 분석만 하고, 구조화된 수정 추천을 메인 에이전트에게 반환하여 적용하거나 위임하는 것

**문제 구분 포인트, 어려운 표현**:
- occasional: 간헐적인
