SCENARIO: You are building a customer support resolution agent using the Claude Agent SDK. The agent handles high-ambiguity requests like returns, billing disputes, and account issues. It has access to your backend systems through custom Model Context Protocol (MCP) tools (get_customer, lookup_order, process_refund, escalate_to_human). Your target is 80%+ first-contact resolution while knowing when to escalate.

QUESTION: To raise first-contact resolution, the team connected three additional MCP servers (loyalty program, shipping carrier, and CRM) alongside the existing support tools. The agent's configuration loads every connected server's tool definitions up front rather than discovering tools on demand, so **the agent sees 19 tools per request**. Since the change, logs show it frequently calling the CRM's contact search **instead of** get_customer and the carrier's shipment tracker **instead of** lookup_order, and resolution accuracy has dropped. What is the most effective way to restore reliable tool selection?

**선택지**:

1. Set **tool_choice to any** on **every request** so the agent is always forced to call one of the available tools rather than answering in text
2. **Extend the system prompt** with per-request-type guidance listing which of the 19 tools apply and which must be ignored
3. **Introduce a dispatcher tool** the agent invokes at the start of each turn, which returns the name of the backend tool it should call next
4. **Restrict the agent's configuration** to expose **only the handful of tools** support cases actually require, omitting the rest => 정답

**설명**:
겹치는 도구들이 많아서, 잘못된 도구를 호출하는 일이 발생할 때 대응법

**문제 구분 포인트, 어려운 표현**:
- Introduce: 도입하다
- omitting the rest: 나머지는 생략하면서
