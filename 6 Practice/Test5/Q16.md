SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: The pipeline needs a new utility that parses raw git diff output into the structured findings format the review bot posts. Claude's first two attempts at the utility handle typical diffs but break on renames, binary files, and empty commits, and one version misses the 200 ms parse-time budget. **Which workflow** most reliably converges on a correct implementation?

**선택지**:
1. Write a test suite first **covering expected behavior**, the rename, binary, and empty-commit edge cases, and the 200 ms budget, then **iterate** by sharing failing test output => 정답
2. Have Claude generate the implementation and its own test suite together in one pass, then ask the same session to review the result and fix anything it finds => 구현체와 테스트 수트를 한 번에 스스로 작성하게 만들면, 구현체의 오류나 편향(Bias)이 테스트 수트에도 동일하게 반영되므로 오답임
3. Document the rename, binary, and empty-commit edge cases plus the latency target in CLAUDE.md, then regenerate the implementation in a fresh session and inspect the output => CLAUDE.md는 개별 유틸리티의 세부 엣지 케이스와 벤치마크 목표를 기록하는 곳이 아님.
4. Rewrite the prose specification in more detail on each attempt, describing every edge case and the latency target in full sentences so Claude can infer the exact behavior

**설명**:
- LLM 기반 코딩 에이전트(Claude Code 등)를 사용할 때 가장 안정적이고 효율적으로 목표 코드에 수렴(Converge)시키는 방법은 "실행 가능하고 검증 가능한 피드백 루프(Executable Test Feedback Loop)"를 구축하는 것입니다.
- 테스트 조건들을 모두 검증할 수 있는 테스트 수트(Test Suite)를 작성하고, Claude에게 구현을 시킨 뒤 실패하는 테스트 결과(Failing test output 및 스택 트레이스)를 피드백으로 주면서 반복 수정(Iterate)하도록 하면, 모델이 목표 동작을 객관적이고 정확하게 파악하여 신뢰성 높게 성공적인 구현체로 수렴하게 됩니다.

**문제 구분 포인트, 어려운 표현**:
- iterate: 반복하다
- inspect: 검사하다
- prose: 글(산문)로 된
- specification: 명세서
- prose specification: 자연어 명세서
- attempt: 시도(시도하다)
- infer: 추론하다
