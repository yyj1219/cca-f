SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: A pull request touching 18 files across your service's API handlers and shared type definitions goes through the automated review. The single-pass review that ingests all 18 files together **gives thorough comments on the first few files** but only **superficial notes on the rest**, flags a pattern in one file while approving identical code in another, and misses a type mismatch between a handler and the client module that consumes it. How should you restructure the review to fix these failures?

**선택지**:
1. Switch the review to a model with a larger context window and extended thinking enabled so a single pass can hold **all 18 files at full analysis depth**
2. Review each changed file in **its own focused pass for local** issues, **then run** a separate integration pass that examines **cross-file data flows and shared types** => 정답
3. Restrict the review input to the diff hunks only, omitting full file contents, so the model's attention is not spread across entire files
4. Run the identical full-PR review three times independently and post only the findings that appear in at least two of the three runs to filter out inconsistency

**설명**:
- 대량의 파일(18개 파일)을 하나의 프롬프트에 한꺼번에 넣고 검토시킬 경우, LLM의 Attention(주의력) 분산 문제 및 Context Window 내 정보의 피로도 때문에 문제가 생긴다.
  - 앞부분 파일만 집중적으로 분석하고 뒤쪽 파일은 피상적으로(Superficial) 넘어가게 됨.
  - 서로 다른 파일 간 동일한 코드 패턴에 대해 상충되는 평가를 내림
  - 파일 개별 분석과 파일 간 연관 관계(타입 일치 여부 등) 분석이 얽혀 둘 다 제대로 수행하지 못함.
- 가장 모범적인 방법은 **검토 단계를 두 가지로 분리**(Two-Pass/Two-Phase)하는 것
  - 1단계 (Local Pass)
  - 2단계 (Integration Pass)

**문제 구분 포인트, 어려운 표현**:
- superficial: 피상적인
- hunks: 조각
