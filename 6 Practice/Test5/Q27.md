SCENARIO: You are building a structured data extraction system using Claude. The system extracts information from unstructured documents, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle edge cases gracefully and integrate with downstream systems.

QUESTION: A legal-tech firm's structured data extraction pipeline keeps its date normalization rules in a configuration file composed of dozens of repeated, near-identical rule blocks. The agent needs to **change exactly one rule** and issues an Edit call, but the call fails: old_string appears in multiple places, and because every block shares the same neighboring lines, enlarging old_string with adjacent context still **cannot isolate a single occurrence**. How should the agent complete the modification reliably?

**선택지**:
1. **Expand old_string** with additional surrounding lines from the rule block to force a unique match
2. **Retry the Edit with replace_all** set to true so every matching occurrence is updated in one call
3. Switch to Bash and apply the change with a sed command addressed to the target line number
4. **Read the full file**, then Write the complete modified content with **only the target occurrence changed** => 정답

**설명**:
- 전체 파일을 읽고, 수정하고, 다시 써서 정확히 하나의 규칙만 바꾼다.

**문제 구분 포인트, 어려운 표현**:
- cannot isolate a single occurrence: 단 하나의 일치 항목만 격리(특정)할 수 없습니다
- 전체 파일을 읽어도 정답일 수 있다
- the target occurrence changed: 변경된 목표 항목
