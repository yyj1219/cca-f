SCENARIO: You are building a customer support resolution agent using the Claude Agent SDK. The agent handles high-ambiguity requests like returns, billing disputes, and account issues. It has access to your backend systems through custom Model Context Protocol (MCP) tools (get_customer, lookup_order, process_refund, escalate_to_human). Your target is 80%+ first-contact resolution while knowing when to escalate.

QUESTION: The coordinator manages several specialized subagents, including an escalation-prep subagent whose description states that it compiles structured handoff summaries for human agents. Production traces show that after the coordinator has already concluded a case must be escalated, automatic subagent matching sometimes routes the handoff work to the billing-analyst subagent instead, producing incomplete summaries for the receiving human. What is the most direct way to ensure the escalation-prep subagent handles this step once the coordinator has decided to escalate?

**선택지**:
1. Instruct the coordinator to **name the escalation-prep subagent explicitly** when it decides to escalate, since naming a subagent directly invokes it instead of relying on description matching. => 정답
2. Add a PreToolUse hook that scans each delegation prompt for escalation-related keywords and rewrites the requested subagent type to escalation-prep whenever they are detected.
3. Move the full escalation-prep procedure into the coordinator's own system prompt so it produces handoff summaries itself **without delegating to any subagent**.
4. Expand the escalation-prep subagent's description with detailed trigger phrases and emphatic wording so automatic matching selects it more reliably for escalation-related work.

**설명**:
- 멀티 에이전트 오케스트레이션 패러다임(Agentic SDK 등)에서 상위 에이전트(Coordinator)가 하위 서브에이전트에게 작업을 라우팅하는 방식은 크게 두 가지가 있습니다:
  - 설명 기반 자동 매칭 (Automatic Description Matching)
  - 명시적 지정 호출 (Explicit Naming/Invocation)
- 상위 에이전트(Coordinator)가 이관 필요성을 판단한 시점부터는 '어떤 에이전트에게 맡길지' 유추할 필요가 없습니다. 프롬프트를 통해 코디네이터가 이관 결정 시 목표 서브에이전트(escalation-prep)의 이름을 명시적으로 지정하여 호출하도록 지시하면 라우팅 오발송을 100% 방지할 수 있는 가장 직접적이고 확실한 해결책이 됩니다.
