SCENARIO: You are building a customer support resolution agent using the Claude Agent SDK. The agent handles high-ambiguity requests like returns, billing disputes, and account issues. It has access to your backend systems through custom Model Context Protocol (MCP) tools (get_customer, lookup_order, process_refund, escalate_to_human). Your target is 80%+ first-contact resolution while knowing when to escalate.

QUESTION: You add a specialized billing-analysis subagent, defined programmatically through the SDK's **agents parameter**, to handle disputed charges. Before delegating, the coordinator has already called get_customer and lookup_order and holds the customer's account details, the disputed order, and the customer's description of the problem. The coordinator then invokes the subagent with the prompt "Analyze this billing dispute and recommend a resolution." In testing, the subagent's recommendations are generic and never reference the specific account, order, or dispute. What change fixes this?

**선택지**:
1. Move the customer and order data into the subagent's AgentDefinition prompt so it loads as part of the subagent's system prompt on every invocation
2. Include the retrieved customer record, order details, and the customer's stated dispute directly in the **delegation prompt** sent to the subagent => 정답
3. Expand the subagent's description field to instruct it to consult the parent conversation's earlier tool results before analyzing the dispute
4. Add the Agent tool to the coordinator's allowedTools so prior tool results are forwarded automatically when the subagent is spawned

**설명**:
서브 에이전트에게 데이터를 전달하려면 위임 프롬프트(Delegation prompt)에 명시적으로 컨텍스트를 넘겨줘야 함

**문제 구분 포인트, 어려운 표현**:
- specialized: 전문화된
- disputed: 분쟁
- delegation prompt: 위임 프롬프트
