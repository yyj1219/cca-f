SCENARIO: You are building a customer support resolution agent using the Claude Agent SDK. The agent handles high-ambiguity requests like returns, billing disputes, and account issues. It has access to your backend systems through custom Model Context Protocol (MCP) tools (get_customer, lookup_order, process_refund, escalate_to_human). Your target is 80%+ first-contact resolution while knowing when to escalate.

QUESTION: In the resolution agent's loop, a **multi-concern** customer message produces a response with stop_reason "tool_use" whose content includes **two tool_use blocks**: one for get_customer and one for lookup_order, **each with its own id**. The current loop implementation executes only the first tool_use block it finds and sends back one tool_result; the **follow-up API** request then fails with a **400 error**. How should the loop process a response like this?

**선택지**:
1. Combine **both tool outputs into one tool_result** block that references **the first tool call's id** so the results arrive together in a single block
2. Return the single tool_result it produced and **rely on Claude to re-request** the tool whose results it did not receive on the next iteration
3. Execute every tool_use block in the response and **return a matching tool_result** for **each block's id** in the single next user message => 정답
4. Send each tool_result in its own **separate user message**, making one API call after each result so the results arrive in order

**설명**:
- Claude가 단일 응답 차례(Turn)에서 여러 개의 도구 사용 요청(tool_use 블록들)을 생성한 경우, API 규약에 따라 클라이언트는 요청받은 모든 tool_use 블록에 대응하는 tool_result 블록을 빠짐없이 만들어 단일 user 메시지에 담아 모델로 돌려주어야 합니다.
- 모델이 한번에 2개 이상의 도구(get_customer, lookup_order)를 호출하면, 각 도구 호출마다 고유한 id가 부여된 tool_use 블록이 생성됩니다.
- 요청받은 tool_use 블록의 일부만 처리하고 나머지 ID에 해당하는 tool_result를 누락한 채 후속 API를 호출하면, API 서버는 tool_use의 ID 짝이 맞지 않는 유효하지 않은 메세지 구조로 판단하여 400 에러를 반환합니다.
- 응답에 들어있는 모든 tool_use 블록을 순회하며 실행하고, 각각의 tool_use_id에 대응하는 tool_result 블록들을 생성하여 하나의 user 메시지 배열에 담아 API를 재호출해야 정상적으로 다음 턴이 진행됩니다.

**문제 구분 포인트, 어려운 표현**:
- each with its own id: 각각 고유한 아이디를 가진
- rely: 의존하다
