SCENARIO: You are building a structured data extraction system using Claude. The system extracts information from unstructured documents, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle edge cases gracefully and integrate with downstream systems.

QUESTION: The extraction pipeline populates a boolean conflict_detected field that routes documents into a manual review queue. The current prompt tells Claude to "set conflict_detected to true when the document's data looks inconsistent or unreliable." In production the flag is erratic: some invoices with mismatched totals sail through unflagged, while clean documents get routed to manual review, and the pattern varies between runs. What prompt change makes this flag dependable for downstream routing?

**선택지**:
1. Strengthen the wording so Claude sets the flag only for documents it is genuinely and highly confident contain inconsistent or unreliable data
2. Set the sampling temperature to zero so identical documents are always evaluated the same way and the flag value becomes fully deterministic across runs
3. Run each extraction twice as independent requests and set conflict_detected to true only when both runs independently judge the document inconsistent
4. Define enumerated, testable flag conditions, such as a stated total differing from the summed line items or a field appearing twice with conflicting values

**설명**:
LLM에 "모순되어 보인다(looks inconsistent)"나 "신뢰할 수 없다(unreliable)"와 같이 주관적이고 모호한 기준을 주면, 불안정한 결과를 내놓습니다.
플래그 판단을 안정화하는 가장 확실한 방법은 명확히 열거되고 테스트 가능한(enumerated, testable) 객관적 조건을 프롬프트에 명시하는 것입니다.

**문제 구분 포인트, 어려운 표현**:
- stated total differing: 명시된 총액이 상이함
- enumerated: 열거된
- genuinely and highly confident: 진정으로 매우 확신할 때
