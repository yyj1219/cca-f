SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: Before rolling out automated test generation, an engineer runs a long Claude Code session that maps a payment module's untested code paths and risk hotspots. The team now wants to prototype **two different test-generation strategies** (property-based tests versus example-based tests), each developed **independently** from that same completed analysis, so the two prototypes can be compared without influencing each other. Which session management approach best supports this?

**선택지**:
1. **Use fork_session** to branch the completed analysis into **two independent lines**, one per test-generation strategy => 정답
2. Run the first strategy, then use /compact to compress its context before running the second in the same session
3. Open **two fresh sessions** and paste a manually written summary of the analysis findings as the first prompt in each
4. Run both strategies in one session sequentially, instructing Claude to disregard the first before starting the second

**설명**:
- fork_session 기능은 이전까지 쌓아둔 심층적 분석 결과(결제 모듈의 테스트되지 않은 코드 경로 및 위험 핫스팟 맥락)를 그대로 유지한 상태에서 완전히 독립된 두 개의 세션으로 분기해 줍니다.
- 따라서 두 가지 테스트 생성 전략(Property-based vs. Example-based)이 공통의 분석 컨텍스트를 완벽히 공유하면서도, 서로의 대화 기록에 영향을 주거나 오염시키지 않고 독립적으로 프로토타입을 개발하고 비교할 수 있습니다.
