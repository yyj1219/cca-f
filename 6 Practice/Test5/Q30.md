SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow with custom slash commands, CLAUDE.md configurations, and understand when to use plan mode vs direct execution.

QUESTION: Your team is automating a standard workflow that runs whenever a new module is added to the codebase: generate an interface summary, write docstrings for public functions, create unit test stubs, and update the documentation index. **The steps and their order are identical** for every module, and the team wants **predictable behavior** that is easy to regression-test. An engineer proposes letting Claude decide at runtime **which subtasks to perform** based on **what it discovers in each module**. Which decomposition approach should the team adopt?

**선택지**:
1. Adopt **dynamic adaptive decomposition** that generates subtasks per module at runtime, since adaptive plans handle fixed sequences at no extra cost
2. Implement a fixed sequential pipeline in which **each step's output feeds the next**, since every step is known up front => 정답
3. Spawn a coordinator agent whose **subagents deliberate on the right subtasks** for each module before any of the steps execute
4. Send **one comprehensive prompt** covering all four steps so Claude can balance the summary, docstrings, tests, and index update in a single pass

**설명**:
계획을 사전에 정해두고, 그에 맞게 진행하는 방식을 추천하는 것

**문제 구분 포인트, 어려운 표현**:
- identical: 동일한
- predictable behavior: 예측 가능한 동작
- regression-test: 회귀 테스트
- dynamic adaptive decomposition: 동적 적응형 분해
- each step's output feeds the next: 각 단계의 출력이 다음 단계의 입력으로 전달되는
- deliberate: 토의하는 (심사숙고하는)
- subagents deliberate on the right subtasks: 알맞는 하위 작업에 대해 심사숙고하는 서브에이전트들 (복수형)
- comprehensive: 포괄적인
- one comprehensive prompt: 하나의 포괄적인 프롬프트
