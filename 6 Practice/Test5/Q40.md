SCENARIO: You are building a structured data extraction system using Claude. The system extracts information from unstructured documents, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle edge cases gracefully and integrate with downstream systems.

QUESTION: The extraction agent runs on the Claude Agent SDK. An MCP server exposes mcp__docstore__search_passages, which queries the indexed document store and returns matching passages together with document IDs, page numbers, and relevance scores that downstream provenance validation requires. The tool's description currently reads only "Searches documents." Logs show the agent instead runs the built-in Grep tool over a raw text export directory, so its results arrive with no provenance metadata. The agent still legitimately uses Grep to inspect local schema and configuration files. Which change most directly fixes the tool preference?

**선택지**:
1. Rewrite the MCP tool's description to detail its indexed search, the provenance metadata it returns, and when to use it instead of raw file search => 정답
2. Set the tools option to an empty array so no built-in tools remain in context and the agent can only reach documents through the MCP server
3. Add a scoped permission rule such as Grep(exports/*) to disallowedTools so the agent is denied whenever it searches the raw export directory
4. Add a system prompt instruction telling the agent to always prefer tools from connected MCP servers over built-ins whenever both could apply

**설명**:
Claude 시스템에서 도구 선택이 올바르게 이뤄지도록 하는 방법 - MCP 설명 상세화
