SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow with custom slash commands, CLAUDE.md configurations, and understand when to use plan mode vs direct execution.

QUESTION: While debugging the project's shared caching layer with Claude Code, the team identified three defects **whose fixes interact**: correcting any one of them changes the correct behavior for the other two. They wrote a single message that lists each defect's symptom and file, and Claude Code produced a patch that fixed each defect in isolation; the combined change reintroduced the first defect. What should the team change about the prompt?

**선택지**:
1. Revise the message to explain the fix interactions in the shared module and the invariants to preserve (유지해야 할 불변 조건) => 정답
2. Replace the prose defect descriptions with issue tracker ticket IDs and let Claude infer the details from titles
3. Send each defect in a separate message and have Claude commit each fix fully before describing the next one => 상호작용이 존재하는 상황에서 메시지를 분리하면, 나중에 적용한 커밋이 이전 커밋의 올바른 동작을 깨뜨려 여전히 결함이 재발하게 됩니다.
4. Prefix each defect description with IMPORTANT so Claude treats all three with equal priority in one pass

**설명**:
프롬프트에 단순 증상과 파일 위치만 나열하면 LLM은 각 결함을 개별적이고 독립적인 단위 문제로 인식하여 결합 시 상충되는 패치를 생성합니다. 
이를 방지하려면 수정 사항 간의 복잡한 상호작용(Fix interactions)과 수정 과정에서 시스템이 어떤 경우에도 반드시 유지해야 하는 불변 조건/규칙(Invariants to preserve)을 **프롬프트에 명시적으로** 작성해 주어야 합니다.

**문제 구분 포인트, 어려운 표현**:
- interact: 상호작용하는
- reintroduced: 다시 발생시키다
- Revise: 수정하다
- interactions: 상호작용
- invariants: 불변 조건 (불변 상태)
- prose: 글(산문)로 된
- infer: 추론하다
- treats: 논하다, 설명하다
