SCENARIO: You are building a structured data extraction system using Claude. The system extracts information from unstructured documents, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle edge cases gracefully and integrate with downstream systems.

QUESTION: Your team keeps its extraction conventions (nullable field handling, enum normalization rules, schema-validation retry guidance) in a CLAUDE.md file inside pipelines/extractors/. Engineers always launch Claude Code from the repository root. They notice the conventions are honored only in sessions where Claude has already read source files under pipelines/extractors/; sessions that touch other parts of the repository ignore the conventions entirely. Running /memory confirms the subdirectory file exists and is listed among the memory file locations. What should the team do to make the conventions apply in every session?

**선택지**:
1. Add YAML frontmatter with a paths glob to the **subdirectory CLAUDE.md** so Claude Code loads it **eagerly at launch** => 정답
2. Delete the root CLAUDE.md, since rules in the subdirectory file override and cancel conflicting root-level rules at startup
3. Move the conventions into the root CLAUDE.md, **since subdirectory memory files load only when Claude reads files under that subtree** => 정답
4. Run /clear at the start of every session to flush the stale memory cache so the subdirectory file is re-read

**설명**:
- 하위 디렉토리의 CLAUDE.md 메모리는 Claude가 해당 하위 경로의 파일에 접근(On-demand)할 때만 컨텍스트에 포함됩니다.
- 따라서 프로젝트 전체 또는 세션의 시작 시점부터 모든 작업에 해당 컨벤션을 공통 적용하려면, 세션 실행 시 항상 자동으로 로드되는 루트 경로의 CLAUDE.md로 컨벤션 내용을 이동해야 합니다.

**문제 구분 포인트, 어려운 표현**:
- extraction conventions: 추출 규약
- the conventions are honored: 컨벤션이 준수된다
- subdirectory CLAUDE.md: 하위 디렉토리에 위치한 CLAUDE.md
- eagerly at launch: 실행 시점에 즉시(eagerly)
- since subdirectory memory files load only: 하위 디렉토리의 메모리 파일만 로드 되므로
