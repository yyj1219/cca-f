SCENARIO: You are building a structured data extraction system using Claude. The system extracts information from unstructured documents, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle edge cases gracefully and integrate with downstream systems.

QUESTION: An engineer on this team started a long extraction-debugging session with claude -n extraction-debug, launching Claude Code with a --mcp-config flag that connected a custom schema-validation MCP server. The next morning the engineer runs claude --resume extraction-debug. The full conversation history, tool results, model, and permission mode all come back, but Claude reports that the schema-validation tools are no longer available. What should the engineer do to continue the session with those tools working?

**선택지**:
1. Ask Claude within the resumed session to reconnect the missing tools, since MCP server connections are managed conversationally after a session starts => 대화로는 MCP 서버는 추가 불가
2. Rerun the **resume command with** the original **--mcp-config flag** included, since resumption does not reapply launch-time flags like MCP server configuration => 정답
3. Fork the session with --fork-session before resuming, since a forked copy re-initializes external MCP server connections while a direct resume does not => 새 세션 ID로 분기할 뿐, MCP 초기화 동작은 일반 resume과 동일함
4. Switch to claude --continue instead of --resume, since continuing the most recent session restores its complete launch configuration including MCP flags => --continue와 --resume은 launch-time 플래그 복원 규칙이 완전히 같음. 차이는 "가장 최근 세션" vs "지정한 세션"뿐.

**설명**:
Claude에서 세션을 다시 시작할 때, 이미 연결된 맞춤형 스키마 검증 MCP 서버를 계속 사용하게 하려면 "원래 사용했던 --mcp-config 플래그와 함께 다시 claude --resume 명령을 실행"해야 함.
