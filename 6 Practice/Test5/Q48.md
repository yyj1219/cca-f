SCENARIO: You are building a customer support resolution agent using the Claude Agent SDK. The agent handles high-ambiguity requests like returns, billing disputes, and account issues. It has access to your backend systems through custom Model Context Protocol (MCP) tools (get_customer, lookup_order, process_refund, escalate_to_human). Your target is 80%+ first-contact resolution while knowing when to escalate.

QUESTION: Human agents receiving escalations from the agent report that its handoff notes vary widely in structure: some include the order reference and the steps the agent already attempted, while others are a single vague sentence that forces the human to re-gather context from scratch. You **already added a system prompt** instruction listing the required sections of a handoff note, but the structure still varies from case to case. Which change most reliably produces consistently structured handoff notes?

**선택지**:
1. Set the sampling temperature to zero so the agent generates handoff notes with the same structure deterministically on every escalation
2. Restate the handoff requirements at the top of the system prompt with strong emphasis, marking the instruction as critical and mandatory
3. Insert a post-processing step where a second Claude call rewrites each free-form note into the standard structure before it reaches the queue
4. **Add a few example handoff** notes to the prompt, each showing the exact structure: issue summary, order reference, actions attempted, escalation reason => 정답

**설명**:
모델에게 원하는 결과물의 실제 예시(Few-shot Examples)를 프롬프트 내에 직접 포함시키면, 모델이 패턴과 구조를 명확히 모방하여 가장 일관되고 신뢰성 높은 출력을 생성한다.

**문제 구분 포인트, 어려운 표현**:
- single vague sentence: 하나의 모호한 문장
