SCENARIO: You are building a customer support resolution agent using the Claude Agent SDK. The agent handles high-ambiguity requests like returns, billing disputes, and account issues. It has access to your backend systems through custom Model Context Protocol (MCP) tools (get_customer, lookup_order, process_refund, escalate_to_human). Your target is 80%+ first-contact resolution while knowing when to escalate.

QUESTION: Your QA team finds that the agent's self-check step, which runs in the same session immediately after the agent drafts a proposed resolution, almost **never flags flawed refund decisions**. When QA pastes an identical draft resolution into a fresh session along with the same policy criteria, the flaws are consistently caught. How should the evaluation step be redesigned?

**선택지**:
1. **Compact the conversation** before the evaluation step so the policy check runs against a summarized version of the session's history
2. **Delegate the policy check to a reviewer subagent** with its own context window that sees only the proposed resolution and the policy criteria => 정답
3. **Route every proposed refund** and account change through the **escalate_to_human** workflow so a support specialist performs the policy check
4. **Strengthen the system prompt** with an instruction to critically question its own reasoning and re-verify each condition before finalizing 

**설명**:
- 동일 세션 내 셀프 체크의 편향 문제를 해결하는 가장 모범적인 멀티 에이전트 설계 방식은 "독립된 컨텍스트 창을 갖는 검토용 서브에이전트(Reviewer Subagent)"에 검증을 위임하는 것입니다.
- 검토 서브에이전트에게는 이전 생성 과정의 노이즈나 추론 내역을 제거하고, 오직 [제안된 해결책 초안]과 [검증해야 할 정책 기준]만 인풋으로 전달(Context Isolation)해야 객관적이고 정확한 검증이 가능해집니다.

**문제 구분 포인트, 어려운 표현**:
- the flaws: 결함들
- never flags flawed refund decisions: 환불 결정을 잡아내지 못 한다
- identical draft resolution: 초안 해결책
- the flaws are consistently caught: 결합들이 일관되게 감지된다.
- Delegate the policy check to a subagent: 에이전트에 정책 점검 위임
