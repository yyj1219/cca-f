SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: The pipeline's review job must determine whether a pull request's change to a shared utility module breaks any of its callers elsewhere in the repository. The current review prompt tells the agent to Read every file under src/ before commenting; reviews now exhaust the context window and the resulting feedback has become vague and generic. Which TWO prompt changes align the investigation with the recommended incremental exploration pattern? (Select TWO.)

**선택지**:
1. Instruct the agent to **Grep for the names** of the modified functions to locate call sites, then Read only **the files that matched** => 정답
2. Keep reading **all of src/** but instruct the agent to Read the files in dependency order so the most important content lands earliest in context
3. Instruct the agent to Glob for the names of the modified functions, since Glob returns the files containing them with less overhead than Grep
4. Instruct the agent to **begin** with the files in **the diff**, then Grep for **imports of those modules** and Read consuming files as needed => 정답

**설명**:
- 변경점이 있는 함수 이름을 검색(Grep)하여 실제로 호출하는 위치(Call sites)만 먼저 찾아낸 뒤, 검색 결과에 일치하는 파일만 선별적으로 읽는(Read) 방식은 점진적 탐색의 대표적 예시
- diff(변경점)에 포함된 핵심 파일부터 출발하여, 해당 모듈을 참조하는(imports) 다른 파일들을 Grep으로 추적하고 필요한 파일만 단계적으로 읽어나가는 방식 역시 점진적 탐색 원칙에 완벽히 부합한다.

**문제 구분 포인트, 어려운 표현**:
- vague: 모호한
