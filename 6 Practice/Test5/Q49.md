SCENARIO: You are building a structured data extraction system using Claude. The system extracts information from unstructured documents, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle edge cases gracefully and integrate with downstream systems.

QUESTION: The system extracts a company's annual revenue from filings where the executive summary and the audited financial statements sometimes state different figures (for example, $4.2M in the summary and $4.35M in the statements). The output schema defines annual_revenue as a **single required number**, and logs show the model silently picks one figure whenever the two disagree, so downstream analysts never learn a discrepancy existed. Which schema and design change best addresses this?

**선택지**:
1. **Change the field to an array of value entries**, each recording the figure and where it appeared in the document, plus a flag marking that the entries conflict
2. Add a prompt rule stating the audited financial statements always take precedence, so the model extracts the tabular figure whenever the two values differ
3. Add a validation-retry loop that re-sends the document with the flagged error whenever downstream reconciliation detects an inconsistent revenue value
4. Keep the single scalar field but require a per-field confidence score, routing low-confidence revenue extractions to human review before downstream delivery

**설명**:
- 기존 스키마가 annual_revenue를 단 하나의 숫자로 요구(single required number)했기 때문에, 문서 내에 상충하는 정보(4.2M vs 4.35M)가 존재하더라도 모델은 스키마 제약 조건을 맞추기 위해 둘 중 하나를 임의로 고를 수밖에 없었습니다.
- 충돌하는 수치들과 각 출처 위치(요약서, 재무제표 등)를 모두 기록할 수 있도록 단일 숫자가 아닌 객체 배열(Array of value entries) 구조로 스키마를 개편해야 합니다.
- 또한 conflict 플래그를 추가함으로써 하류 분석가가 정보 불일치가 존재한다는 사실을 보장받고 명확히 인지할 수 있도록 보장합니다.

**문제 구분 포인트, 어려운 표현**:
- annual revenue: 연간 매출
- discrepancy: 불일치 (모순)
