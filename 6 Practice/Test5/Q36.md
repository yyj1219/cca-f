SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: Your team keeps its standard review prompt in a /review-scope command stored in .claude/commands/ so both developers and the pipeline share it. Each invocation needs to target a different part of the codebase, for example /review-scope src/billing or /review-scope src/api. How should the command's markdown file be written so it receives the value supplied at invocation time?

**선택지**:
1. Add an argument-hint entry to the file's frontmatter that documents the target path the command expects
2. Store the target path as a static configuration entry in .claude/settings.json and update it before each run
3. Include the $ARGUMENTS placeholder in the command's markdown body where the target path should appear => 정답
4. Create a separate markdown file in .claude/commands/ for each target directory the team regularly reviews

**설명**:
- 슬래시 커맨드 설계하는데, 커맨드가 호출될 때마다 다른 부분의 코드를 대상으로 하도록 하는 방법
- $ARGUMENTS 사용하면 원하는 위지를 지정할 수 있음
- argument-hint 프론트매터는 사용자에게 입력하라고 안내만 할 뿐, 값을 본문으로 전달해주지 않음
- .claude/settings.json 에 정적 항목은 설정 정보를 담는 곳으로, 호출할 때마다 값이 다르게 전달되는 동적 입력용이 아님

**문제 구분 포인트, 어려운 표현**:
- static configuration entry: 정적 설정 항목
