SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: Your pipeline's review agent calls an MCP static-analysis tool that returns extremely verbose JSON. You registered a hook on the **PostToolUse** event, matched to that tool, that **trims each result** down to the actionable findings before Claude reasons about it. This works well, but the **analysis server intermittently crashes mid-scan**, and on those runs the hook never executes: the failed call's raw error output reaches the model without any trimming or annotation. What should the team do so that failed calls are also intercepted and processed before Claude consumes them?

**선택지**:

1. Register the interception logic on the **PostToolUseFailure** event as well, since failed tool calls do not trigger PostToolUse => 정답
2. Change the PostToolUse matcher from the specific tool name to a wildcard so the **hook fires on every outcome** of every tool
3. Move the interception into a **PreToolUse** hook matched to the same tool, since PreToolUse fires regardless of the tool's outcome
4. Add logic inside the existing PostToolUse callback that inspects tool_response for error indicators and handles those cases

**설명**:
- PostToolUse: 도구가 성공적으로 실행되어 정상적인 결과를 반환했을 때만 트리거됩니다.
- PostToolUseFailure: 도구 실행 중 예외/에러가 발생하거나 서버가 중단(Crash)되어 실패했을 때 트리거됩니다.
- 도구 실행 실패 시 발생하는 에러 메시지를 가로채어 정리/가공하려면, 성공 시 동작하는 PostToolUse와 별개로 실패 이벤트를 전담하는 PostToolUseFailure 이벤트 핸들러에도 동일한 가로채기(Interception) 및 트리밍 로직을 등록해야 합니다.

**문제 구분 포인트, 어려운 표현**:
- extremely verbose JSON: 매우 장황한 JSON
- trims each result: 결과를 다듬는
- failed call's raw error: 실패한 호출의 원시 에러
- annotation: 주석
- sinse: ~이므로
- regardless: 상관없이
- indicators: 지표
- inspects: 검사하다
