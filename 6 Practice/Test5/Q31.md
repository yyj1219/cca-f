SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow with custom slash commands, CLAUDE.md configurations, and understand when to use plan mode vs direct execution.

QUESTION: A senior engineer uses Claude Code for a large refactoring task. Subtle regressions, such as behavior changes in edge cases, keep slipping through and are only caught later during human pull request review. When the engineer inspects the session transcript, Claude's reasoning shows it explicitly considered those edge cases during the refactor and concluded its changes were safe. The team wants **Claude to catch these regressions itself** before a PR is opened. Which practice is most likely to surface them?

**선택지**:
1. **Enable extended thinking** in the refactoring session so Claude deliberates more thoroughly before it finalizes each edit
2. End the refactoring session with an **instruction directing** Claude to **critique** its own edits against the original code's behavior
3. Have a separate Claude Code session with no access to the refactoring conversation **review the resulting diff** => 정답
4. Resume the refactoring session later with --resume and ask Claude to re-examine the completed changes with fresh attention

**설명**:
독립적인 검토는 이전 판단에서 벗어나 새로운 시각으로 코드를 보게 해야 한다.

**문제 구분 포인트, 어려운 표현**:
- Subtle regressions: 미세한 리그레션(성능/기능 저하)
- behavior changes: 동작 변경
- slipping through: 간과되어 빠져나가고
- session transcript: 세션 기록(트랜스크립트)
- explicitly considered: 명시적으로 고려했다
- concluded: 결론냈다
- regressions: 리그레션(성능/기능 저하)
- surface: 드러내다
- extended thinking: 확장 사고
- instruction directing: 지시 사항
- critique: 비판적으로
