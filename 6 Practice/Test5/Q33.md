SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow with custom slash commands, CLAUDE.md configurations, and understand when to use plan mode vs direct execution.

QUESTION: This team is scripting a documentation pipeline around the Messages API: for each source file, Claude **must first populate an extract_metadata tool** (capturing function signatures, parameters, and return types) before a later enrichment step adds usage examples. The initial request's tools array includes extract_metadata alongside the enrichment tools, and the pipeline must guarantee that the metadata extraction step always happens first. Which TWO actions correctly implement this design? (Select TWO.)

**선택지**:

1. Read the extraction output directly from the initial response, since forcing the tool makes the API run extract_metadata server-side in one request
2. Set tool_choice to {"type": "tool", "name": "extract_metadata"} on the first request rather than "any", which could let enrichment run first => 정답
3. Treat stop_reason "end_turn" on the forced call as confirmation that extraction and the final answer completed in a single turn
4. Read the tool_use block from the response, execute extract_metadata in pipeline code, and send back a tool_result before starting enrichment => 정답

**설명**:
- Anthropic Messages API에서의 강제 도구 호출(tool_choice)과 도구 실행 생명주기(Tool Execution Lifecycle)
  - tool_choice: "any"로 설정하면 사용 가능한 도구 중 아무거나 호출하므로 보강 도구(enrichment tool)가 먼저 실행될 위험이 있습니다.
  - 특정 도구를 첫 턴에서 확실히 순서상 가장 먼저 실행하도록 보장하려면 tool_choice: {"type": "tool", "name": "extract_metadata"}와 같이 해당 도구명을 명시적으로 지정(Forced Tool Choice)해야 합니다.
  - Anthropic API 서버는 도구를 '직접 실행'해주지 않으며, 모델이 전달한 입력 인자(Arguments)가 담긴 tool_use 블록을 반환할 뿐입니다.
  - 클라이언트(파이프라인 코드)는 이 tool_use 블록의 파라미터를 읽어 실제 메타데이터 추출 작업을 실행한 뒤, 그 결과를 tool_result 블록으로 구성하여 다음 user 메시지로 다시 API에 전달해야만 보강(Enrichment) 단계로 자연스럽게 진행할 수 있습니다.
- API 응답에서 tool_use 블록을 받아 로컬 파이프라인에서 도구 로직을 수행한 후, 그 결과값(tool_result)을 다시 Messages API로 돌려주는 것이 도구 호출의 올바른 완료 단계(Protocol)입니다.

**문제 구분 포인트, 어려운 표현**:
- around the Messages API: Messages API를 기반으로
- enrichment step: 보강 단계
