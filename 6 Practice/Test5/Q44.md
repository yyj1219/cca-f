SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: The pipeline's coverage-audit step asks the agent to enumerate every test file so it can verify that each modified component has a corresponding test. The agent calls Glob with the pattern **/*.test.tsx, but the monorepo has grown to roughly 350 such files; the tool returns only 100 paths along with a truncation indicator, and the audit now flags missing tests that actually exist. How should the team make the enumeration complete?

**선택지**:
1. Accept the truncated output, since modification-time sorting means the omitted files are the oldest and least relevant to open pull requests
2. Increase CLAUDE_CODE_GLOB_TIMEOUT_SECONDS so the tool has enough time to enumerate and return every matching test file path
3. Have the agent scope Glob calls per package via the path parameter, splitting further until no call reports truncation, then merge the lists => 정답
4. Swap the Glob call for Grep with the same **/*.test.tsx pattern, since Grep is not subject to the file enumeration cap

**설명**:
- Glob 도구는 패턴에 맞는 파일 경로를 찾지만, 결과는 캡(기본 100개)으로 제한되어 있음. 각 패키지 또는 디렉토리별로 호출하여 결과가 잘리면 더 작은 범위로 계속 호출한 후에 머지해서 제한을 해결함.
