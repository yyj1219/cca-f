SCENARIO: You are building a structured data extraction system using Claude. The system extracts **information from unstructured documents**, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle **edge cases** gracefully and integrate with downstream systems.

QUESTION: After the team migrated purchase order extraction to **tool_use** with a strict **input_schema**, every extraction now parses cleanly and passes schema validation. However, downstream reconciliation jobs keep finding purchase orders where the **due_date falls** before the order_date and where **quantity multiplied by unit_price does not match** the extended line total. What should the team do to address these failures?

**선택지**:

1. **Add code-level validation of business rules**, such as date ordering and totals reconciliation, and route failing extractions to a retry or review path => 정답
2. Set **temperature to zero** so the model deterministically places every value in its correct field and computes each line total accurately
3. Replace the extraction tool with **prompt-only JSON** instructions and an assistant prefill, since tool_use appears to be corrupting field assignments
4. Make **every schema field required** and tighten type constraints so the schema itself rejects extractions that contain misplaced or inconsistent values

**설명**:
LLM API의 tool_use 및 JSON Schema 기능은 형식적 구문 검증(Structural/Syntactic Validation)에 특화되어 있습니다. 
즉, 데이터 간의 논리적 관계나 비즈니스 규칙(Business Rules)은 JSON Schema 단에서 검증할 수 없습니다.
JSON Schema가 거르지 못하는 비즈니스 규칙(날짜 순서 유효성, 산술 결과 대조 등)은 애플리케이션 코드 수준(Code-level validation)에서 검증 로직을 구현해야 합니다.

**문제 구분 포인트, 어려운 표현**:
- code-level validation of business rules
- route failing extractions: 실패한 추출 결과 라우팅
