SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: The pipeline's review step uses a tool whose input schema requires a severity field constrained to the enum values critical, high, medium, and low, and the merge gate blocks any pull request with a critical finding. Audits show that when Claude **cannot determine** a finding's real impact from the diff alone (for example, whether a risky code path is actually reachable), the schema still forces it to pick one of the four levels, and it often picks critical, causing false merge blocks. The merge gate must keep consuming severity as a machine-checkable field. What is the best schema-level change?

**선택지**:
1. Add a prompt instruction telling the model to assign a severity level only when it is highly confident in the classification
2. Make the severity field nullable so the model can return null whenever the finding's impact cannot be determined => JSON Schema 상에서 단순히 null을 허용하는 것보다 도구의 도메인 의미를 나타내는 명시적 Enum 값(unclear)을 추가하는 것이 파이프라인의 타입 안정성과 가독성을 높이는 더 나은 스키마 설계 방식입니다.
3. Replace the severity enum with a free-text string field so the model can describe impact in its own nuanced words
4. **Add an unclear** value to the severity enum so ambiguous findings are labeled honestly and routed to **human triage** => 정답

**설명**:
- LLM 기반 에이전트 도구의 입력 스키마(Input Schema)를 설계할 때, 모델이 정보 부족 등의 이유로 모호한 판단을 내려야 하는 상황에서 명확한 선택지(Enum)만 존재하면 환각이나 과잉 분류(Over-classification)가 발생합니다.
- 열거형(Enum)에 unclear(또는 unknown)라는 유효한 상태 값을 추가하면, 키마가 여전히 Enum 구조를 유지하므로 Downstream 파이프라인(병합 게이트)에서 if (severity == 'unclear') 형태의 기계적 자동화 조건 처리가 가능합니다.
- 모델에게 "확실하지 않음"을 표현할 수 있는 명시적 출구를 제공하여 솔직한 라벨링을 유도하고, 모호한 건만 사람의 검토(Human triage)로 라우팅하여 오진단으로 인한 PR 차단을 막을 수 있습니다.

**문제 구분 포인트, 어려운 표현**:
- severity field: 심각도 필드
- highly confident: 높은 신뢰도
- ambiguous findings: 모호한 발견사항
- human triage: 사람에 의한 트리아지(분류 및 검토)
