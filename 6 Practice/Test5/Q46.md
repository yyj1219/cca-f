SCENARIO: You are using Claude Code to accelerate software development. Your team uses it for code generation, refactoring, debugging, and documentation. You need to integrate it into your development workflow with custom slash commands, CLAUDE.md configurations, and understand when to use plan mode vs direct execution.

QUESTION: During long autonomous sessions, Claude has twice run npm run db:migrate:prod from the repository, applying schema changes to the production database. To stop this, the team configured a command hook on the **PostToolUse** event, matched to the Bash tool, that inspects the command and exits with code 1 whenever it detects a production migration. In testing, the migration command still executes every time. Which two changes together make the rule deterministically enforceable? (Select two.)

**선택지**:
1. Exit with code 2 when a violation is detected, since **exit code 1** is treated as **a non-blocking error** for hook events
2. Add the prohibition to the project CLAUDE.md marked IMPORTANT so the model treats it as a top-priority rule in every session
3. Increase the hook's timeout so it always finishes evaluating the Bash command before the migration begins executing
4. Attach the check to a **PreToolUse hook instead**, since PostToolUse fires only after the tool call has already executed

**설명**:
- Claude Code의 훅 시스템(Hooks) 가이드라인에 따르면, PreToolUse 훅에서 도구 실행을 명시적으로 차단/거부(Block/Deny)하고 프로세스를 정지시키려면 종료 코드 2(exit code 2)를 반환하도록 설계되어 있다. (종료 코드 1 등은 단순 에러 로그 출력 후 계속 진행될 수 있다.)

**문제 구분 포인트, 어려운 표현**:
- deterministically enforceable: 확실하게 강제하기
