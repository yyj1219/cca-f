SCENARIO: You are building a structured data extraction system using Claude. The system extracts information from unstructured documents, validates the output using JavaScript Object Notation (JSON) schemas, and maintains high accuracy. It must handle edge cases gracefully and integrate with downstream systems.

QUESTION: The extraction pipeline currently sends every extraction to a compliance reviewer. After measuring 96% accuracy on a 2,000-document labeled validation set that spans invoices, supplier contracts, and shipping manifests, engineering leadership proposes **sending extractions directly to downstream systems without review**. What analysis must be completed before approving this change?

**선택지**:
1. Have the model **rate its own confidence** (자체적으로 신뢰도 평가) on each validation document and verify that average confidence stays above the accuracy target
2. Expand the labeled validation set to 10,000 documents and confirm the aggregate accuracy holds at the larger sample size
3. Compare the aggregate accuracy against the measured error rate of the human reviewers and automate if the model scores higher
4. Recompute **accuracy separately** for **each document** type and **each extracted field**, confirming no segment falls materially below the aggregate => 정답

**설명**:
- LLM 추출 시스템 평가에서 가장 흔히 발생하는 오류 중 하나는 "전체 평균 정확도(Aggregate Accuracy)"의 착시입니다.
- 본문의 데이터셋은 청구서(Invoices), 계약서(Contracts), 적하목록(Manifests) 등 여러 종류의 문서로 구성되어 있으며, 문서 내에도 금액, 날짜, 계약자명 등 다양한 필드가 존재합니다.
- 전체 정확도가 96%라 하더라도, "계약 금액" 필드의 정확도가 70%로 낮거나 "공급업체 계약서"의 정확도가 80%에 불과하다면 컴플라이언스 검토를 생략했을 때 심각한 비즈니스/법적 리스크가 발생합니다.
- 시스템 자동화 전환 승인 전에는 반드시 문서 유형별, 필드별로 정확도를 세분화하여 분석(Slice Analysis)하고 치명적인 하락이 없는지 확인해야 합니다.

**문제 구분 포인트, 어려운 표현**:
- accuracy target: 정확도 목표
- Recompute accuracy: 정확도 재계산
