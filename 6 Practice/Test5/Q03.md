SCENARIO: You are integrating Claude Code into your Continuous Integration/Continuous Deployment (CI/CD) pipeline. The system runs automated code reviews, generates test cases, and provides feedback on pull requests. You need to design prompts that provide actionable feedback and minimize false positives.

QUESTION: The pull request review agent in this pipeline connects to a custom MCP server exposing a tool named search_code, described as "searches code for patterns." The tool actually queries an indexed, organization-wide code search service covering every repository, not just the checked-out one. Logs show the agent almost always uses the built-in Grep tool instead, so reviews miss breaking changes to callers in other repositories. What is the most effective fix?

**선택지**:
1. **Rename the tool** to search_org_repositories and **describe the cross-repository indexed data it returns that local search cannot**
2. Add a system prompt rule instructing the agent to **always prefer MCP tools** over built-in tools when both could apply
3. Set tool_choice to force the MCP search tool so every request that needs a search is guaranteed to route through it
4. Remove Grep from the review agent's allowed tools so the MCP search tool becomes the only way to search for patterns

**설명**:
- LLM 기반 에이전트가 여러 도구(Built-in Grep vs. Custom MCP Tool) 중 하나를 선택할 때, 도구의 이름(Name)과 설명(Description)은 모델의 선택 판단에 결정적인 영향을 미칩니다.
- "항상 MCP 도구를 선호하라"는 무조건적인 시스템 프롬프트 규칙은 너무 넓은 범위를 건드리고, 불필요하게 MCP 도구를 사용하게 만드는 부작용이 있다.
- tool_choice를 사용해 MCP 검색 도구를 강제하면 모든 검색 요청이 타 리포지토리 전체 검색으로 몰려 자원 낭비 및 지연 시간이 발생하고, 상황에 따른 자율적 도구 선택이 불가능해집니다.
